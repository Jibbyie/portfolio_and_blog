About the Project

This was my first real multiplayer project in Unity using NGO. It’s a 2D dash-and-damage prototype where up to 4 players can join, fight, and rematch in a networked arena. I built the full networking stack, player syncing, damage system, and win tracking from scratch.

Technical Highlights

  • Spawn system that dynamically assigns prefabs and syncs ownership.
  • Health syncing with NetworkVariables and RPC-based damage reporting.
  • Dash collision logic with server-side validation to ensure fairness.
  • Match win detection, synced game over UI, and rematch reset system.
  • Client-specific UI updates including player names, HP bars, and match status.

Development Focus

  • Understanding authoritative server logic and network ownership.
  • Building a fully network-safe player loop from join to rematch.
  • Managing client sync, disconnections, and UI states reliably.
  • Learning the limits of RPCs, NetworkVariables, and scene objects.

What I Learned

  • How to structure a clean, server-authoritative multiplayer loop in Unity.
  • Dealing with sync issues and ownership logic bugs in NGO.
  • Using RPCs properly alongside NetworkVariables.
  • The importance of separating concerns to avoid spaghetti code.
  • Why modular design matters in multiplayer systems.

What I’d Improve On

Honestly, the code is kind of slapped together. A lot of systems are overly coupled — for example, PlayerMove.cs handles movement, dash logic, damage processing, health syncing, collision events, and UI updates… basically everything. It works, but it's messy. I’d refactor it to break up responsibilities properly and make things modular. Right now, a bunch of scripts are too tightly connected, which makes scaling or reusing them difficult. I want to revisit this from scratch and rebuild it more cleanly in the future.
